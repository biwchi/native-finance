# iOS client

Open `FinanceTracker.xcodeproj` in Xcode 26 or newer to build the iOS 26 Liquid Glass controls. Simulator Debug builds connect to `http://127.0.0.1:3010` to match the backend's IPv4 listener. Using `localhost` can reach another development server listening on IPv6 port 3010 and return a 404 even while this backend is running.

## Icons

Generic app icons use the free Hugeicons Stroke Rounded set through the [Hugeicons Swift package](https://github.com/iSapozhnik/hugeicons-swift), pinned to revision `81caddf04ce5352652ffaa619562f02477dbf35d`. This is a community-maintained Swift wrapper around `@hugeicons/core-free-icons`. Brand and cryptocurrency marks are bundled as template assets; their sources and usage guidelines are recorded in [`docs/brand-icon-sources.md`](../../docs/brand-icon-sources.md). License notices are included in the app's `ThirdPartyNotices.txt` resource.

Use `AppIcon` for explicitly sized, Dynamic Type-aware icons, `Label(..., icon: ...)` for native labels and menus, and `AppIcons.uiImage(named:)` for UIKit tab items. `AppIcons.artwork` maps stable app identifiers to Hugeicons artwork, while `AppIcons.assetNames` records bundled template assets. Existing Iconoir identifiers and older SF Symbols names remain compatible with saved accounts and categories. Keep using app-owned identifiers in picker choices. Add generic mappings to `artwork` and bundled marks to `assetNames`. Unknown saved names show a tag.

Run `AppIconTests` and `AccentControlContrastTests` when changing icon rendering or the icon catalog. The rendering tests attach light/dark samples to the Xcode test results.

## Test on your iPhone over Wi-Fi

1. Connect your Mac and iPhone to the same Wi-Fi network.
2. Start the backend with `bun run dev` from the repository root. Keep `HOST=::` in `apps/backend/.env` so it accepts both IPv6 and IPv4 connections from your phone. An existing `HOST=0.0.0.0` setting accepts only IPv4 and can cause timeouts on networks where the iPhone reaches the Mac over IPv6. After changing this setting, restart the backend.
3. Select your iPhone as the run destination in Xcode and run the `FinanceTracker Device` scheme. It builds with the Debug configuration and launches without attaching LLDB, so a stalled debugger connection cannot hold the app at its launch screen. Use the original `FinanceTracker` scheme when you need breakpoints.
4. Allow **Local Network** access when the app asks.

Each device Debug build automatically uses `http://<your-Mac-hostname>.local:3010`. Xcode's **Configure API** build step detects the Mac's Bonjour hostname and writes a generated Info.plist into DerivedData. The hostname continues to work when the Mac's Wi-Fi IP changes; no address needs to be committed or switched when returning to the simulator. Local HTTP permission is added only to Debug builds, and requests wait up to 30 seconds for connectivity while you respond to the first permission prompt.

To check connectivity from the iPhone, open `http://<your-Mac-hostname>.local:3010/health` in Safari. Find your Mac's hostname with:

```sh
scutil --get LocalHostName
```

If it does not load, check that the backend is running, allow incoming connections for Bun if the macOS firewall asks, and avoid guest Wi-Fi or VPN configurations that prevent devices from communicating. If local-network access was denied, enable Finance Tracker under **Settings → Privacy & Security → Local Network** on the iPhone, then reopen the app.

If the entire screen stays black after running from Xcode, press **Stop** in Xcode, close Finance Tracker on the phone, then run the **FinanceTracker Device** scheme to rebuild, reinstall, and launch independently of the debugger. Keep the phone unlocked during installation. The initial import has its own setup screen. After it succeeds, subsequent launches show saved local content even when the server is unavailable. This recovery preserves app data and does not require uninstalling the app.

## Override the API address

The iOS app does not read the backend's `.env`. It reads the optional, ignored `apps/ios/.env` file through `scripts/configure-api.sh`. Simulator Debug builds use `http://127.0.0.1:3010`. Physical-device Debug builds and Release builds use `HOSTED_API_BASE_URL` from `apps/ios/.env` when it is present. The local backend's `PORT` must match the simulator URL. Rebuild and run the app after changing its API configuration.

`API_BASE_URL` remains an explicit per-build override. For a different local port or address, set the FinanceTracker target's **Build Settings → User-Defined → API_BASE_URL** for the relevant configuration, then rebuild. Leave it empty for automatic simulator, hosted-device, and Release selection. For example, `http://192.168.1.20:3010` uses your Mac's current Wi-Fi IP; it must be updated if that IP changes. A command-line build can pass the same setting:

```sh
xcodebuild -project FinanceTracker.xcodeproj -scheme FinanceTracker \
  -configuration Debug -destination 'generic/platform=iOS' \
  API_BASE_URL=http://192.168.1.20:3010 build
```

`API_TOKEN` in `apps/ios/.env` is added to API requests. Keep that file out of source control. Release builds use `API_BASE_URL` when supplied, otherwise `HOSTED_API_BASE_URL`, then the value in `FinanceTracker/Resources/Info.plist` as a final fallback. Release builds never add Debug local-network permissions.

The account editor uses the same grouped form sections as Settings. Add Account focuses the name field automatically. Save is hidden while the keyboard is open; scroll to dismiss the keyboard. Icon suggestions appear only when the name matches catalog entries.

The account picker and finance screens read the shared local SQLite database. **All Accounts** is the default; selecting an account or month queries the local data immediately. The menu shows the first four accounts in the saved order. **View Accounts** opens the complete accounts sheet, where each account shows its balance in its currency and **All Accounts** shows the combined balance in the display currency. Tapping an account or **All Accounts** selects it and closes the sheet. Swipe left on an account for **Edit** and **Delete**; deletion requires confirmation. Use the toolbar's **Edit** mode to tap into account details, reorder, or delete accounts. Reordering also changes which four accounts appear in the menu. **Add Account** and account editing open at full sheet height.

## Account and transaction currencies

Accounts have an optional **Initial balance**, defaulting to zero, in the account currency. Enter the amount held before the transactions you record, or a negative amount for money owed. It contributes to account and All Accounts balances, with normal currency conversion, but creates no transaction and does not affect income, spending, or budgets. Editing it corrects the starting amount rather than setting today's balance. Changing account currency keeps that numeric amount in the new currency. Account types have been removed.

Changing an account's currency sets the default for new transactions and the currency used to display that account. Existing transactions and recurring schedules keep their saved amounts and currencies. With a specific account selected, transaction lists show converted amounts with an approximation mark and the original amount underneath. All Accounts shows each transaction in its original currency, while summary totals use the default display currency. Missing exchange rates leave the original amounts visible.

The transaction editor always shows the saved currency. To correct a currency entered by mistake, open **Details → Currency**. This keeps the numeric amount unchanged. For a recurring transaction, the correction also updates its schedule for future occurrences. Changing account or display currency never performs a bulk conversion of saved transactions.

## Debts

Choose **Debt** when adding a transaction, select the account you lend from, and choose a recipient from the horizontal carousel. Its first item, **All**, opens the complete recipient sheet. Tap a recipient to select it and close, or use **Add recipient** to create and select someone new. Swipe a recipient for **Edit** or **Delete**. In either recipient sheet, **Edit** shows drag handles for reordering and delete controls. The saved order is used by the carousel and debt groups, and syncs across devices. Deleting a recipient requires confirmation; recipients with outstanding loans must have those loans marked as returned or moved to another recipient first. **Debts** has a direct **+** button for lending and a separate **Settings** button for managing recipients. Recipient settings and create/edit sheets follow the Accounts layout, with grouped rows, inline titles, a close button, and a full-width bottom action. The editor shows the recipient’s icon beside their name, suggested icons when the name matches, and a horizontal color picker. New recipients focus the name field; Save appears after dismissing the keyboard. Changes to names, icons, and colors appear on existing loans immediately. Debt transactions reduce the account balance and available budget, but do not count as income or expense spending. They cannot repeat or have expense categories.

Open **Home → Finances → Debts** using the labeled Finances button in the dashboard toolbar. This screen includes outstanding debt transactions across all accounts and months, a total in the default display currency, recipient counts, and a balance for each recipient. Tap a transaction to edit it. If exchange rates are unavailable, separate currency totals are shown. Swipe a loan and choose **Delete · returned** once the money has been returned to its original account. Deleting removes the outstanding loan and restores the account balance; recipients remain available for future loans.

Apply the backend migration with `bun run db:migrate` before using this client with an existing database.

## Navigation

The smaller camera button to the left of Add opens **Scan purchases**. Close floats at the top left; flashlight, shutter, and photo-library controls float along the bottom, directly over the preview with no title bar or bottom panel. On iOS 26 they use clear Liquid Glass with a subtle tint; older versions use translucent material. Camera access is optional when choosing an existing photo. Photos are rotated upright, reduced to 2048 pixels on the longest edge, and re-encoded as JPEG without location metadata before upload.

**Attach document**, beside **Choose photo**, opens Files for PDF, CSV, TSV, XLS, and XLSX documents. Choose one file up to 10 MB with at most 750 transactions. The app reads a bounded copy through the file provider, sends it to the existing AI connection with the selected account and local categories, and opens **Review document**. The filename identifies the review. Tap a row to edit it, swipe to remove it, or use **Submit** to save the remaining drafts together. Discarding adds nothing. Document drafts survive relaunch and can be submitted offline; the original file bytes are not saved with the drafts. Failed extraction keeps the attachment available for retry, replacement, or returning to the camera. Closing cancels the request.

Documents use the scan policy for receipt totals, transaction direction, currency conversion, account defaults, and categories. Statement balances, summary totals, and repeated headers are excluded; rows on different pages or sheets remain distinct. The document response includes a required overflow flag so the app can reject reported truncation instead of accepting that partial result. The [OpenAI file input API](https://developers.openai.com/api/docs/guides/file-inputs) processes PDF text and page images and accepts spreadsheet files. Its spreadsheet processing covers up to the first 1,000 rows per sheet, so use a small transaction export rather than a full workbook. Recognition and completeness still require user review. Local tests use mocked responses and never call AI.

Scanning uses the existing Quick Entry AI connection and selected account context. Each receipt produces a draft for its paid total; separate receipts or transaction records can produce several drafts. Product screenshots default to a one-time expense at the main current price, ignoring financing offers and conditional bonus prices unless explicitly requested. Scanning preserves the source currency for the server to convert into the chosen account currency. The review supports editing, removing, discarding, and saving drafts, with no finance writes until Save. Reviewed drafts survive app restarts and save offline. Completed quick-entry reviews and scans share the activity pill and the Drafts list. Close or swipe down on a review to keep it for later; discard it from the pill or list. Saving writes the transactions and removes only their draft batch in one local database transaction. Older saved quick-entry reviews move into this collection on launch. Unfinished typed Quick Entry text stays in memory when the composer is dismissed or a scan is saved. It clears after a successful typed submission or when the app terminates; it is never restored on relaunch. Failed recognition keeps the photo available for retry or retake; closing the scanner cancels recognition. Camera and flashlight behavior requires a physical iPhone to verify.

Scan and typed Quick Entry use separate prompts built from one category, account, and payment policy. The model extracts structured facts; the backend validates explicit choices, resolves calendar dates, and calculates installment amounts. Explicit user category choices take priority, followed by merchant matches to category names or examples, including subcategories. Source bank labels are secondary evidence. Unreadable amounts remain blank and must be entered before saving. The review shows the original input or “Scanned photo”, transaction rows, and a single conversion banner when needed. Converted transactions retain the original amount below the account-currency amount. Rows have no notes, generated hints or warnings, and drafts need no separate AI confirmation. Transaction notes remain editable in Details. Typed Quick Entry preserves the user's description of the item, purpose or context as a note unless an explicit note instruction overrides it. Photo and document scans also form concise notes from supported source details. Person or business prefers the seller and can use an identifiable purchase platform when the seller is unknown. Unsupported details remain empty. The Person or business field uses the optional `counterparty` field. Canceled records and unrelated interface text are ignored. Display-only source data and review messages are not requested, returned or stored. Verification uses local fixtures and mocked providers, with no paid AI calls.

Home is the main screen. Its trailing toolbar groups the icon-only **Finances** button with a 2×2 grid icon and **Settings**, with Settings on the far right. Finances opens a permanent directory for **Recurring**, **Debts**, and **Budget**, including when these features have no data. The centered Add Transaction button belongs to the dashboard, so pushed pages cover it along with the dashboard. There is no bottom navigation menu.

**Recurring** shows a centered amount with **Expenses / Income / All** and **Day / Week / Month / Year** selectors, defaulting to Expenses and Month. Day and Week cover the next 1 and 7 days, Month the next 30 days, and Year the next 12 months. All shows net cash flow (income minus expenses). Projections expand actual scheduled dates in UTC, preserve month-end and leap-day anchors, respect end dates, and convert complete totals into the display currency. The type filter also applies to active schedules and recorded transactions. Add opens transaction entry with recurrence enabled and the selected transaction type.

**Budget** opens an overview for the selected account and Home’s selected month (or the current month when Home uses a different period). It keeps the summary at the top, then surfaces over-budget pool and category limits with links to their transactions. Each pool has a separate card with a stable color, its remaining amount, and a current-month elapsed-time marker. Tap a pool to expand its categories and the **View pool transactions** link; standalone categories appear below the pools. Category limits retain all subcategory spending, with a note when part of that spending belongs outside the displayed pool. The marker is informational and is hidden for past and future months. The month picker changes the spending report. Each account, including **All Accounts**, has one saved budget that applies to every month. **Settings** edits that shared setup; changing or clearing limits also updates reports for previous months. Debt transactions do not count as budget spending.

## Settings

**Default currency** shows the selected currency code on the right. **Display** groups dark theme, the first day of the week, rounding, and the budget summary option.

**Display → Budget summary** is on by default. When no monthly limit is set, Home and Budget use the sum of pool limits and category limits outside pools. Category limits within a pool do not add to the total. An explicit monthly limit always takes precedence. Turn this setting off to use only an explicit monthly limit for the budget summary. With no configured limits, the existing spending and net summaries remain.

**Recurring reminders → Show on Home** controls how many days before a recurring transaction its reminder appears (default: 3; configurable from 1 to 7 days before). Older saved values are clamped to this range. Home shows the nearest upcoming transaction for the selected account, independently of the summary period. Multiple qualifying schedules appear as a stack; a single schedule appears as one card. Reminders display the original currency and full amount precision and have no tap action.

**Display → First day of week** offers Monday, Sunday, and Saturday. It initially uses the device calendar’s week start when supported, otherwise Monday. Older unsupported selections use the same fallback. The preference updates calendar pickers and the Week / Bi-weekly filters on Home. **Round totals** displays whole amounts on summary cards, Budget limits and forecasts, account balances, and debt totals. Stored amounts and transaction editing keep their original precision.

Support destinations are read from the app Info.plist: `APP_STORE_REVIEW_URL`, `SUPPORT_URL`, `PRIVACY_POLICY_URL`, and `TERMS_OF_USE_URL`. Use HTTPS URLs (the support URL also accepts `mailto:`); the App Store review URL should be the app's actual listing with `action=write-review`. Until real destinations are supplied, the rows explain that the destination is unavailable.

**Delete all data** requires a warning confirmation followed by typing the exact lowercase word `confirm`. The client clears local finance data and persists a reset operation in the same SQLite transaction. It sends that reset automatically when connected. A workspace generation barrier keeps delayed uploads and responses from restoring deleted content; new local entries wait behind the reset. Display preferences remain. This backend currently has one personal workspace and no user authentication: the operation applies to the entire connected workspace. The user-account deletion row is enabled and uses the same warning and typed-confirmation flow. Until a user identity service exists, the final step reports that account deletion is not available and leaves data intact.

## Local storage and sync

The shared GRDB 7.11.1 database lives at `Application Support/FinanceTracker/finance.sqlite`. Apply backend migrations through 0016 before running this client. Migration 0014 keeps the most recently edited budget per account with its pools and category limits, then removes the saved month. The local SQLite upgrade makes the same change and preserves pending offline edits. First launch imports a consistent snapshot before enabling editing. Later launches use the saved database immediately.

Finance saves, ordering, transfers, reviewed Quick Entry batches, budgets, and recurrence work locally. A single worker attempts uploads after a commit, then reads server changes. Connectivity changes, foreground entry, and an iOS background refresh request also trigger it. iOS chooses when suspended apps receive execution time; the app does not depend on a fixed background schedule.

Routine synchronization has no visible indicators. Completed deletions are resolved automatically after checking a complete server snapshot. Unfinished changes appear under **Settings → Review changes**, grouped with their dependent edits and showing the saved entry details. Missing accounts never cause automatic loss or reassignment of surviving transactions. Saved changes can be exported as JSON; discarding them requires reviewing the affected entries first. A missing synced copy is not labeled as deleted. Quick Entry interpretation needs a connection, uses local account/category context, and preserves the prompt and reviewed drafts. Committing reviewed drafts works offline.

All screens share a persistent USD-based exchange-rate table. Successful refreshes are reused for 24 hours. Failed refreshes leave cached conversions usable; missing rates leave original amounts visible.

See [the sync protocol and validation guide](../../docs/local-first.md) for database, API, reset, and test details.

## CSV tables

**Settings → CSV tables** provides **Export CSV** and **Import CSV**. Both read local data and work offline. Export selects all accounts or one account and all dates or an inclusive date range. It preserves recorded amounts and currencies, including individual recurring payments and both sides of transfers. It does not export recurring schedules or account opening balances.

Import reads a UTF-8, comma-separated file on the device, validates every row, and opens the same editable review used by quick entry. Tap a transaction to edit it or swipe to remove it. **Submit** saves the remaining rows in one local database transaction. Dismissing or discarding the preview adds nothing. A failed submission saves no rows, and CSV review never overwrites an unfinished AI review. Imported transactions use the app's normal sync after local submission; the CSV file is never uploaded for processing.

The **Import help** button explains each column and saves an example CSV. Required columns are `date`, `type`, `amount`, and `account`. Optional columns are `currency`, `category`, `counterparty`, `note`, and `recipient`. An empty `counterparty` value leaves Person or business blank. Dates accept `YYYY-MM-DD` in the device time zone or ISO 8601 timestamps with an explicit zone. Amounts must be non-zero with a decimal point and up to four fractional digits. A leading minus is accepted and removed because `type` determines whether the transaction is an expense, income, or debt. Debt rows require an existing recipient. Names resolve case-insensitively to existing accounts, categories, and recipients; ambiguous names require an ID. Subcategories use `Parent › Child`. Empty currency uses the account currency, with no conversion. CSV draft editing also preserves the saved amount and currency when changing accounts.

Files may contain up to 5,000 transactions and 5 MB. Unknown columns, invalid values, malformed quoting, and unresolved references produce row errors before review. CSV quoting supports commas, escaped quotes, and embedded line breaks. Exports protect spreadsheet formula text with an apostrophe, which import removes. Import adds new transactions and does not detect duplicates, replace existing records, or recreate recurring schedules.
